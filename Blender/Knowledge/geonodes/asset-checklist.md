### ★ CANONICAL ST3E GEONODE BUILD RECIPE — START HERE (hub for all GN-modifier work)
This file is the single entry point for creating/editing ST3E Geometry-Nodes modifiers under `Blender/Geonodes/`. The ordered recipe (each step links the Knowledge page with the details):
1. **Target Blender 5.0; build headless** when the live MCP isn't connected (`blender.exe --background --factory-startup <file> --python <s>.py`; flush stdout + `os._exit(0)` after save). Prefer the live MCP to verify. → [Headless Blender and automation](../headless-and-automation.md#feedback_blender_version_and_headless), [Headless Blender and automation](../headless-and-automation.md#reference_blender_mcp)
2. **Ship a demo object**: create a fitting primitive, attach the GN modifier (`obj.modifiers.new('NODES').node_group=ng`), select+activate, save a FULL mainfile (`save_as_mainfile`) — NEVER asset-only `libraries.write`. → [Geonode asset files](asset-files.md#feedback_geonode_file_needs_object)
3. **Author the graph (Blender 5 idioms):** menu inputs need a string `default_value` & the modifier override is an INT → [Geonode sockets, interfaces and menus](sockets-and-menus.md#feedback_gn_menu_socket_default); ONE menu can't drive two Menu Switches → master MenuSwitch(INT)→Index Switch → [Geonode sockets, interfaces and menus](sockets-and-menus.md#feedback_gn_menu_to_index_switch); GN math is float32 (guard huge values / use a Switch to original at extremes). Frame + label every node like code.
3b. **ADDING a socket to an EXISTING published tool:** interface identifiers are handed out in creation order (`Socket_0`, `Socket_1`, …, and every `new_panel` burns one too), and a rebuild-from-scratch script re-mints them the same way. So inserting a `sock()` call in the middle of a panel **renumbers every socket below it** and silently re-points the overrides already saved on users' modifiers (their Gap value lands on Seed, etc.). Declare new sockets LAST — after the Geometry output — then `iface.move_to_parent(item, panel, index)` to file them where they belong in the UI. The move is cosmetic; identifiers travel with the socket. Verify by dumping `identifier→name` before and after and diffing. (Renaming a socket is always safe — that was the `Fit Tiles To Boundary` case.)
4b. **Direction/axis of effect:** every deform modifier with a direction/axis exposes it quick-by-axis (X/Y/Z menu) AND custom via an external empty (an `Object` menu item + `Direction Object` socket = the empty's local +Z); center deformers also get `Use Object As Center`. Reusable helper `GNG_ObjectDirection`. → [Geonode techniques](techniques.md#feedback_gn_object_direction_axis)
4. **Deformer conventions (if it has a pivot):** editable `Center` (vector, TRANSLATION) + `Show Center Gizmo` (3 Linear arrow gizmos + CROSS marker, overlay-only); `Symmetry` (abs-dist-from-center) for gradient-along-axis ones; per-axis `Affect X/Y/Z` filter for scaling ones; single-direction deformers get a Displace/Axis menu; toggleable `Show Deformation Preview` bbox lattice (`GNG_DeformCage`). → [Geonode techniques](techniques.md#feedback_gn_deformer_center_gizmo_symmetry)
5. **Organise the UI in panels** (`interface.new_panel` + `move_to_parent`): Selection top-level → base-params panel → Affect Axes → Center → Preview. → [Geonode techniques](techniques.md#feedback_gn_deformer_center_gizmo_symmetry)
6. **Lay out the nodes** with the deterministic `tidy_layout` (columns by longest path, frame bands, generous gaps; frame loc=(0,0) makes child loc absolute). → [Geonode layout](layout.md#feedback_gn_node_layout_spacing). **Layout tooling relocated 2026-07-02** to `Blender/Addons/LLMGeonodePipeline/` (was `Geonodes/geonode_route_tidy.py` → now `tidy_layout.py`): prefer `run_pipeline.py -- <GN_X>` which applies `tidy_layout` then GATES the save on `layout_audit.py` rules R1–R5 (no overlaps / reroutes-clear / left-to-right / frames-labeled / row-clearance) AND geometry-unchanged — both goals must pass. `layout_audit.py` is the shared rule set for the deterministic engine AND the GeoNode Layout MCP. See skill `geonode-layout-mcp`.
7. **Publish as asset** (see checklist below): `asset_mark`; catalog = the matching **leaf sub-catalog** (see the UUID table below — NOT the flat `f9ab2fa9…` ST3E root, which has held no direct assets since the 2026-07-20 split); `tags.new("ST3E")`; `is_modifier=True`, `is_tool=False`; fill socket `description`s AND `asset_data.description` (the browser tooltip). Keep publishing in a **separate metadata-only script** (`_build/publish_gn_<x>.py` pattern) once a file has been tidied or the user has added test objects to it — re-running the builder would throw both away.
8. **Give it an icon**: the Asset-Browser preview is generated by the pipeline in `Blender/Geonodes/_icons/` (recipe + effect-check gate + headless render + embed). Read `_icons/ICONS.md` and `_icons/GOTCHAS.md`; run `coverage.py` there to see which modifiers still lack one. → [Geonode asset files](asset-files.md#project_geonode_icon_pipeline)
9. **Verify** (headless eval or live MCP): deform happens, identity at neutral param, no NaN, gizmo on/off vert count equal (overlay), preview cage subdivides+deforms. Clean up throwaway `_*.py`.
Edge→face / region-fill / Repeat-Zone field tricks: [Geonode nodes, fields and domains](nodes-and-fields.md#feedback_gn_edge_to_face_bool_interp). **The full roster of what already exists (and each tool's params) is the "DONE" lists lower in this file — keep it updated as new geonodes are built.**

For a Geometry Nodes group in `Blender/Geonodes/*.blend` to show up in Blender's **Add Modifier → ST3E** quick-pick menu, ALL of these must hold (checked live 2026-05-31):

1. **Marked as asset** — right-click node group → *Mark as Asset*.
2. **Assigned to an ST3E LEAF sub-catalog** (catalog file: `Blender/blender_assets.cats.txt`; asset-library root = `Blender/`). Since commit `8f1e6b7` (2026-07-20) the flat root was split four ways and **every** modifier re-pointed, so the root now holds no direct assets — a group left on it shows up outside all four groups in the browser. UUIDs:
   | catalog | UUID |
   |---|---|
   | `ST3E` (root — **do not use for modifiers**) | `f9ab2fa9-3a4e-491a-abaa-558cd5c029d0` |
   | `ST3E/Deform` | `bacd112a-8e87-47c2-afbc-818a11c75c08` |
   | `ST3E/Generate` | `8872522f-45b7-4541-a557-5b69bcbfcee2` |
   | `ST3E/Modify` | `9b90781b-f051-4cdb-9dcb-c8909914a87b` |
   | `ST3E/Scatter & Instancing` | `25b9ecc2-4cf7-41b3-83c3-152a2eccbc77` |

   **Audit trick:** any modifier authored AFTER the split silently inherits the old flat UUID if it was copied from an older build script. Sweep every file with `libraries.load(f, assets_only=True)` in one headless pass and print `asset_data.catalog_id` — that is how `GN_Mosaic` was caught (it was the only one still on the root).
3. **Valid as modifier** — first interface INPUT socket is Geometry AND there is a Geometry OUTPUT socket.
4. **Modifier asset trait ON** — `node_group.is_modifier = True`. UI: Geometry Nodes editor → N-panel → **Group** tab → asset-trait **Type: Modifier / Tool** checkboxes. **New groups default both OFF**, so a perfectly asset-marked + catalogued group with correct sockets STILL won't appear in the modifier menu until *Modifier* is ticked. This was exactly the `GN_ShearGeometry` bug.
5. **`ST3E` asset TAG** — `node_group.asset_data.tags.new("ST3E")`. This is SEPARATE from the catalog (step 2): the catalog is the Asset-Browser library folder; the tag is metadata the user filters/groups by. All ST3E modifiers carry `tags=['ST3E']` (ShearGeometry, MirrorGroup, ExtrudeFace, SetAttribute, AttributeTransfer, SimpleTransformMesh, SplitEdgeByAttribute, GN_Weld, GN_Delete — the latter was normalized from `StephkoTools`→`ST3E` on 2026-06-02; RandomizePosition added 2026-06-02; **Inflate, Spherify, Twist, Taper, Wave, Bend, Smooth, Stretch added 2026-06-03**). **Always add this tag when creating a new ST3E geonode**, and normalize any stray non-ST3E tag you encounter.

**Why:** the Asset Browser shows an asset regardless of trait, so a missing `is_modifier` flag is invisible there — the only symptom is absence from the Add-Modifier menu. Menu (enum) input sockets are fine for modifiers and are NOT a blocker.

**Full create-a-new-ST3E-geonode recipe (headless, Blender 5):** `ng = bpy.data.node_groups.new("GN_X","GeometryNodeTree")`; build interface (Geometry in + Geometry out + params, set menu defaults per [Geonode sockets, interfaces and menus](sockets-and-menus.md#feedback_gn_menu_socket_default)); wire nodes; frame+label them; then `ng.asset_mark(); ng.asset_data.catalog_id="f9ab2fa9-3a4e-491a-abaa-558cd5c029d0"; ng.asset_data.tags.new("ST3E"); ng.is_modifier=True; ng.is_tool=False`; fill socket `description`s; `save_as_mainfile`. `GN_Weld.blend` was built exactly this way.

**How to apply / verify quickly (via [Headless Blender and automation](../headless-and-automation.md#reference_blender_mcp)):**
- Read trait: `ng.is_modifier`, `ng.is_tool`. Set+save: `ng.is_modifier=True; bpy.ops.wm.save_mainfile()`.
- Non-destructive scan of a closed file: `bpy.data.libraries.load(path, assets_only=True)` to list asset groups, append, inspect `is_modifier`/interface, then `bpy.data.node_groups.remove`.
